## 2. 추가된 클래스

### `TimeSlotInterval`

Firestore에 저장하기 전의 순수한 시간 구간입니다.

```kotlin
data class TimeSlotInterval(
    val startAt: Long,
    val endAt: Long
)
```

`TimeSlot`과 달리 ID, Host, 상태 같은 저장 정보가 없습니다. 시간 계산만 담당합니다.

## 3. 새로 사용한 기술

- Firestore `WriteBatch`
  - 분할된 여러 TimeSlot을 한 번에 저장
- Kotlin `generateSequence`
  - 시작 시각부터 종료 시각까지 슬롯 구간 생성
- Kotlin 확장 함수
  - `TimeSlotInterval.overlaps(timeSlot)`
- JUnit 단위 테스트
  - Firebase 없이 순수 시간 계산 검증
- `LocalDateTime`과 자정 변환
  - `24:00`을 다음 날짜의 `00:00`으로 변환

새 외부 라이브러리는 추가하지 않았습니다.

## 4. 설계 이유

시간 계산을 Repository 내부에 전부 넣지 않고 순수 도메인 함수로 분리했습니다. 그래야 Firebase 없이 테스트할 수 있고 STEP 5에서도 같은 규칙을 재사용할 수 있습니다.

중복 검사는 시작 시간이 같은지만 보는 대신 아래 구간 공식으로 판단합니다.

```text
새 시작 < 기존 종료
그리고
새 종료 > 기존 시작
```

따라서 `10:00~10:30`과 `10:15~10:45` 같은 부분 중복도 잡습니다. 끝과 시작만 맞닿는 경우는 중복이 아닙니다.

여러 문서 저장에는 WriteBatch를 사용했습니다. 하나의 범위 등록 중 일부 문서만 저장되는 상황을 줄이고 한 번에 커밋하기 위한 선택입니다.

UI 검증과 Repository 검증을 모두 둔 이유는 역할이 다르기 때문입니다.

- ViewModel: 사용자에게 빠르게 입력 오류 표시
- Domain/Repository: UI 외 경로에서 호출돼도 잘못된 데이터 차단
