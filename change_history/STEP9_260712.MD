# STEP 9. 공유 링크 / App Links

문서 기준 작업일: 2026-07-12

구현 커밋일: 2026-07-15

STEP 9에서는 Host의 `reservationLinkId`를 HTTPS 예약 링크로 만들고, 복사하거나 Android 공유 시트로 전달할 수 있게 했다. 링크를 연 환경에 따라 설치된 앱의 Host 예약 화면으로 이동하거나 Firebase Hosting 랜딩 페이지를 표시하며, 카카오톡 인앱 브라우저에서 앱을 명시적으로 실행할 수 있는 커스텀 스킴도 제공한다.

공유 링크 형식은 다음과 같다.

```text
https://timelink-af0f6.web.app/host/{reservationLinkId}
```

## 1. 변경된 파일 목록

### Android 앱

- [`app/src/main/AndroidManifest.xml`](../app/src/main/AndroidManifest.xml)
  - `https://timelink-af0f6.web.app/host/**`를 처리하는 App Links intent filter를 추가했다.
  - Android가 도메인 소유권을 검증하도록 `android:autoVerify="true"`를 사용했다.
  - 카카오톡 인앱 브라우저의 “앱에서 열기” 버튼을 위한 `timelink://host/**` 커스텀 스킴 intent filter를 추가했다.

- [`app/src/main/java/com/kkm/timelink/MainActivity.kt`](../app/src/main/java/com/kkm/timelink/MainActivity.kt)
  - 앱이 종료된 상태의 `onCreate()`와 실행 중인 상태의 `onNewIntent()`에서 딥링크를 처리한다.
  - HTTPS App Link와 `timelink://host/{id}` 커스텀 스킴에서 `reservationLinkId`를 추출한다.
  - 로그인 상태가 되면 `host/{reservationLinkId}` Navigation 경로로 이동한다.
  - 예약 링크를 Android Sharesheet로 공유하는 `ACTION_SEND` Intent를 생성한다.

- [`app/src/main/java/com/kkm/timelink/ui/home/HomeScreen.kt`](../app/src/main/java/com/kkm/timelink/ui/home/HomeScreen.kt)
  - 단순 ID 대신 전체 HTTPS 예약 링크를 화면에 표시한다.
  - 전체 링크 복사와 공유 버튼을 제공한다.
  - 공유 동작 자체는 콜백으로 위임해 Composable이 Android Intent를 직접 만들지 않게 했다.

- [`app/src/main/res/values/strings.xml`](../app/src/main/res/values/strings.xml)
  - 예약 링크 기본 URL을 `reservation_link_base_url`로 관리한다.
  - 공유 제목과 공유 시트 제목 문자열을 추가했다.

### Firebase Hosting

- [`firebase.json`](../firebase.json)
  - Hosting public 디렉터리를 `hosting`으로 설정했다.
  - `/host/**` 요청을 `index.html`로 전달하는 rewrite를 추가했다.

- [`hosting/index.html`](../hosting/index.html)
  - 앱 미설치 또는 App Links 미연결 상황에서 표시할 랜딩 페이지를 추가했다.
  - 현재 URL에서 Host 링크 ID를 읽어 화면에 표시한다.
  - `intent://host/{id}#Intent;scheme=timelink;package=com.kkm.timelink;end` 형식으로 앱을 명시적으로 실행하는 버튼을 제공한다.

- [`hosting/.well-known/assetlinks.json`](../hosting/.well-known/assetlinks.json)
  - `timelink-af0f6.web.app` 도메인과 Android 패키지 `com.kkm.timelink`의 관계를 선언했다.
  - Android가 HTTPS 링크를 TimeLink 앱에서 열어도 되는지 검증할 수 있도록 서명 인증서 SHA-256 지문을 등록했다.

참고로 `.firebase/hosting.*.cache`는 Firebase CLI가 생성한 배포 캐시이며 STEP 9의 애플리케이션 설계 파일은 아니다.

## 2. 추가된 클래스와 타입

STEP 9에서는 새로운 Kotlin 클래스, ViewModel, Repository 또는 데이터 모델을 추가하지 않았다. 기존 클래스와 Composable을 확장하고 Hosting 정적 파일을 추가했다.

추가된 주요 함수와 입력값은 다음과 같다.

- `Intent.toReservationLinkId()`
  - 수신한 Intent가 지원하는 링크 형식인지 검증하고 `reservationLinkId`를 반환하는 확장 함수다.
  - 현재 코드는 HTTPS App Link와 `timelink` 커스텀 스킴을 모두 지원한다.

- `TimeLinkApp(deepLinkReservationLinkId, onDeepLinkHandled, ...)`
  - Activity에서 받은 딥링크 ID를 Compose Navigation에 전달한다.

- `HomeScreen.onShareReservationLinkClick`
  - Stateless Composable이 공유 실행을 상위 계층에 요청하기 위한 콜백이다.

Hosting에는 클래스 대신 다음 정적 리소스가 추가됐다.

- `index.html`: 앱 미설치 시 랜딩 페이지와 앱 실행 버튼
- `assetlinks.json`: HTTPS 도메인과 Android 앱의 신뢰 관계

## 3. 새로 사용한 기술

- Android App Links
  - 검증된 HTTPS 링크를 설치된 Android 앱의 특정 화면으로 연결한다.

- Digital Asset Links
  - `/.well-known/assetlinks.json`을 통해 웹 도메인과 앱 패키지 및 서명 인증서의 소유 관계를 증명한다.

- Firebase Hosting
  - 공유 가능한 HTTPS 도메인과 앱 미설치 시 랜딩 페이지를 제공한다.

- Firebase Hosting rewrite
  - 동적인 `/host/{reservationLinkId}` 경로를 하나의 정적 `index.html`로 전달한다.

- Android deep link Intent filter
  - `ACTION_VIEW`, `DEFAULT`, `BROWSABLE` 조합으로 브라우저에서 앱 진입을 허용한다.

- Android custom scheme 및 intent URI
  - `timelink://host/{id}`와 `intent://...#Intent`를 사용해 인앱 브라우저에서 앱 실행 버튼을 제공한다.

- Android Sharesheet
  - `Intent.ACTION_SEND`와 `Intent.createChooser()`로 사용자가 원하는 메신저나 앱을 선택해 링크를 공유하게 한다.

- Compose side effect 처리
  - `LaunchedEffect`로 로그인 상태와 딥링크 입력 변화를 관찰하고, `rememberUpdatedState`로 최신 딥링크 값을 인증 상태 수집 로직에서 참조한다.

- URI 인코딩과 파싱
  - `Uri.encode()`, `Uri.pathSegments`, JavaScript의 `encodeURIComponent()`와 `decodeURIComponent()`를 사용한다.

## 4. 왜 그렇게 설계했는지

공유 링크는 앱 전용 커스텀 스킴이 아니라 HTTPS를 기본 형식으로 사용했다. HTTPS 링크는 카카오톡, 문자, 브라우저 등 어떤 환경에서도 공유할 수 있고 앱이 설치되지 않은 사용자에게도 웹 페이지를 보여줄 수 있다. 또한 PRD에서 요구한 Firebase Hosting 기반 링크와 Android App Links 구조를 그대로 만족한다.

링크에는 Firebase UID가 아니라 공개용 `reservationLinkId`를 사용한다. UID를 외부 URL에 직접 노출하지 않고, 기존 `users.reservationLinkId` 조회 흐름을 재사용하기 위해서다. 링크 ID를 받은 앱은 기존 Host 예약 화면으로 이동하므로 예약 신청 로직을 별도로 복제하지 않는다.

App Links 검증을 위해 Manifest의 `autoVerify`와 Hosting의 `assetlinks.json`을 함께 사용했다. Manifest 선언만으로는 해당 도메인이 실제 앱 소유인지 확인할 수 없으므로, 도메인에 패키지명과 인증서 지문을 공개해 Android가 양쪽 설정을 검증하도록 했다.

앱이 설치되지 않았거나 브라우저가 App Links를 앱으로 전달하지 않으면 Firebase Hosting의 랜딩 페이지가 표시된다. `/host/**`를 단일 HTML로 rewrite하고 JavaScript가 현재 경로에서 ID를 읽으므로 Host마다 별도의 HTML 파일을 만들 필요가 없다.

카카오톡 같은 인앱 브라우저는 검증된 App Link를 바로 외부 앱으로 넘기지 않을 수 있어 랜딩 페이지에 명시적인 실행 버튼을 추가했다. 버튼은 패키지명이 포함된 Android intent URI를 사용하고, 앱에서는 `timelink://host/{id}`를 별도 intent filter와 파서로 처리한다.

딥링크 ID는 Activity의 Compose state로 보관한다. 사용자가 로그아웃 상태에서 링크를 열면 먼저 로그인 화면을 보여주되 ID를 버리지 않고, 로그인 성공 후 Host 예약 화면으로 이동한다. 처리 완료 후 ID를 `null`로 초기화해 recomposition이나 인증 상태 변화로 동일 화면이 반복해서 열리는 것을 방지한다.

`HomeScreen`은 전체 예약 링크를 만들고 복사·공유 요청만 콜백으로 전달한다. Android `Context`와 Intent 생성은 `MainActivity`가 담당하므로 UI를 가능한 한 Stateless하게 유지한다.

## 5. 반드시 이해해야 하는 코드 5곳

### 1) 전체 예약 링크 생성과 공유 UI

파일: [`HomeScreen.kt`](../app/src/main/java/com/kkm/timelink/ui/home/HomeScreen.kt)

`reservation_link_base_url`과 `uiState.reservationLinkId`를 결합해 전체 HTTPS 링크를 만든다. 복사 버튼은 이 전체 링크를 Clipboard에 저장하고, 공유 버튼은 동일한 링크를 `onShareReservationLinkClick`에 전달한다. 화면 표시, 복사, 공유가 동일한 값을 사용해야 링크 형식이 서로 달라지는 문제를 막을 수 있다.

### 2) Android 공유 시트 실행

파일: [`MainActivity.kt`](../app/src/main/java/com/kkm/timelink/MainActivity.kt)

`Intent.ACTION_SEND`에 MIME 타입 `text/plain`, 제목, 예약 링크 본문을 넣고 `Intent.createChooser()`로 실행한다. 특정 메신저 패키지에 직접 의존하지 않으므로 사용자가 설치한 어떤 공유 앱에서도 동작한다.

### 3) App Links 및 커스텀 스킴 intent filter

파일: [`AndroidManifest.xml`](../app/src/main/AndroidManifest.xml)

첫 번째 intent filter는 `https`, `timelink-af0f6.web.app`, `/host/` 조건과 `autoVerify`를 사용한다. 두 번째 intent filter는 랜딩 페이지 버튼이 만드는 `timelink://host/{id}`를 처리한다. Manifest가 링크를 Activity로 전달하고, 실제 ID 검증과 화면 이동은 Kotlin 코드가 담당한다.

### 4) 딥링크 파싱과 로그인 이후 Navigation

파일: [`MainActivity.kt`](../app/src/main/java/com/kkm/timelink/MainActivity.kt)

`Intent.toReservationLinkId()`는 허용된 scheme, host, path 구조만 받아 ID를 추출한다. `onCreate()`와 `onNewIntent()` 모두 이 함수를 호출하므로 앱 종료 상태와 실행 중 상태를 모두 지원한다. `LaunchedEffect(deepLinkReservationLinkId, uiState.isSignedIn)`는 로그인 여부를 확인한 뒤 `host/{id}`로 이동하고 처리된 ID를 제거한다.

### 5) 웹 도메인 연결과 미설치 랜딩 페이지

파일: [`firebase.json`](../firebase.json), [`assetlinks.json`](../hosting/.well-known/assetlinks.json), [`index.html`](../hosting/index.html)

`firebase.json`은 `/host/**`를 랜딩 페이지로 rewrite한다. `assetlinks.json`은 도메인이 TimeLink 앱의 HTTPS 링크 처리를 허용한다는 사실을 Android에 증명한다. `index.html`은 경로에서 ID를 추출하고, App Links가 자동 실행되지 않은 환경을 위해 커스텀 스킴 기반 “앱에서 열기” 버튼을 제공한다. 세 파일이 함께 있어야 설치·미설치·인앱 브라우저 흐름을 모두 처리할 수 있다.

## 검증 및 배포 참고

- STEP 9 구현 당시 Android `assembleDebug`, 단위 테스트, Hosting 및 Digital Asset Links JSON 문법 검증을 통과했다.
- Hosting 파일 변경은 `firebase deploy --only hosting`으로 배포해야 실제 도메인에 반영된다.
- 현재 `assetlinks.json`에는 debug 서명 인증서 지문이 등록되어 있다. Play Store 배포 시에는 Play App Signing 인증서의 SHA-256 지문을 추가해야 한다.
- App Links 검증은 배포된 `https://timelink-af0f6.web.app/.well-known/assetlinks.json`에 Android 기기가 접근할 수 있어야 성공한다.
