# STEP 8. FCM 알림

작업일: 2026-07-12

STEP 8에서는 예약 신청, 승인, 거절 상태 변화를 Cloud Functions에서 감지해 대상 사용자에게 FCM 알림을 보내는 구조를 추가했다. Android 앱은 로그인한 사용자의 FCM 토큰을 Firestore에 동기화하고, 수신한 data message를 시스템 알림으로 표시한다.

## 2. 추가된 클래스와 타입

- `NotificationRepository`
  - 알림 토큰 관련 데이터 계층의 인터페이스다.
  - `syncToken(uid)`, `saveToken(uid, token)`, `clearToken(uid)`을 제공한다.

- `FirebaseNotificationRepository`
  - `NotificationRepository`의 Firebase 구현체다.
  - Firebase Messaging과 Firestore 접근을 담당한다.

- `TimeLinkMessagingService`
  - `FirebaseMessagingService`를 상속한 Android 서비스다.
  - 토큰 갱신과 메시지 수신을 담당한다.

- `NotificationRepositoryModule`
  - `FirebaseNotificationRepository`를 `NotificationRepository`로 바인딩하는 Hilt 모듈이다.

- `FirebaseMessagingModule`
  - 싱글턴 `FirebaseMessaging` 인스턴스를 제공하는 Hilt 모듈이다.

Functions에는 클래스 대신 다음 서버 함수가 추가됐다.

- `notifyReservationRequested`: 새 `PENDING` 예약을 감지해 Host에게 알림을 보낸다.
- `notifyReservationStatusChanged`: `APPROVED` 또는 `REJECTED` 상태 변경을 감지해 Guest에게 알림을 보낸다.
- `sendToUser`: 토큰 조회와 FCM 전송을 공통 처리한다.
- `isInvalidTokenError`: 더 이상 사용할 수 없는 토큰 오류인지 판별한다.

## 3. 새로 사용한 기술

- Firebase Cloud Messaging
  - Android 기기 토큰 발급 및 data message 전송에 사용했다.

- Cloud Functions for Firebase v2
  - `onDocumentCreated`, `onDocumentUpdated` Firestore 이벤트 트리거를 사용했다.

- Firebase Admin SDK
  - 신뢰할 수 있는 서버 환경에서 Firestore 토큰 조회와 FCM 발송을 처리한다.

- FCM data message
  - `title`, `body`, `type`, `reservationId`를 앱에 전달하고 앱이 직접 알림 UI와 클릭 동작을 구성한다.

- Android Notification Channel 및 `NotificationCompat`
  - Android 8 이상 알림 채널과 여러 Android 버전에 호환되는 시스템 알림을 구성한다.

- Android 13 런타임 알림 권한
  - `POST_NOTIFICATIONS` 권한을 Manifest에 선언하고 앱 실행 중 사용자에게 요청한다.

- Hilt 의존성 주입
  - 메시징 서비스와 ViewModel이 구체 Firebase 구현에 직접 결합되지 않도록 Repository를 주입한다.

- Kotlin Coroutines 및 `Task.await()`
  - Firebase 비동기 작업을 순차적인 suspend 함수 형태로 처리한다.

## 4. 왜 그렇게 설계했는지

알림 발송은 Android 앱이 아니라 Cloud Functions에서 담당하도록 했다. 예약 신청이나 상태 변경은 Firestore 문서에 최종 반영된 사실을 기준으로 알림을 보내야 한다. 클라이언트에서 직접 알림을 보내면 앱 종료, 네트워크 중단, 악의적인 호출 때문에 누락되거나 잘못된 대상에게 전송될 수 있다. Firestore 트리거는 데이터 변경이 발생한 뒤 서버에서 실행되므로 발송 기준을 한곳에 모을 수 있다.

FCM 토큰은 공개 프로필인 `users`가 아니라 비공개 문서인 `user_private/{uid}`에 저장했다. 토큰은 특정 기기로 알림을 보낼 수 있는 민감한 식별자이므로 공개 프로필과 분리해야 하며, 이는 `FIRESTORE_SCHEMA.md`의 필드 구조를 그대로 따른 것이다.

Android에서는 ViewModel이나 UI가 Firebase Messaging과 Firestore를 직접 호출하지 않고 `NotificationRepository`를 사용한다. 이 구조는 프로젝트의 MVVM 및 Repository Pattern 규칙을 지키며, 토큰 저장 방식이 바뀌더라도 인증 화면의 변경을 최소화한다.

로그인 성공 시 토큰을 동기화하고 로그아웃 시 토큰을 제거한다. 이를 통해 현재 로그인한 UID와 기기 토큰의 연결을 최신 상태로 유지하고, 이전 사용자가 로그아웃한 기기로 알림이 계속 전달되는 문제를 줄인다. `onNewToken()`도 별도로 처리해 Firebase가 토큰을 교체한 경우 Firestore 값을 갱신한다.

서버는 FCM의 만료 또는 등록 해제 토큰 오류를 감지하면 Firestore의 `fcmToken`을 제거한다. 유효하지 않은 토큰을 계속 재사용하면 발송 실패가 반복되므로 서버가 스스로 데이터를 정리하도록 설계했다.

data message를 사용한 이유는 앱이 알림 채널, 문구, 클릭 Intent를 직접 제어하기 위해서다. `reservationId`를 함께 전달하면 알림을 누른 사용자를 해당 예약 상세 화면으로 연결할 수 있다.

## 5. 반드시 이해해야 하는 코드 5곳

### 1) 예약 변경을 감지하는 서버 트리거

파일: [`functions/index.js`](../functions/index.js)

`notifyReservationRequested`는 예약 문서가 생성됐을 때 `status == PENDING`인지 확인하고 Host UID로 알림을 보낸다. `notifyReservationStatusChanged`는 변경 전후의 `status`가 실제로 달라졌는지 확인한 뒤 `APPROVED`, `REJECTED`만 Guest에게 알린다. 상태 검사가 없으면 메시지 수정처럼 알림과 무관한 문서 업데이트에도 중복 알림이 발생할 수 있다.

### 2) 대상 토큰 조회와 FCM 전송

파일: [`functions/index.js`](../functions/index.js)

`sendToUser(uid, body, type, reservationId)`는 `user_private/{uid}`에서 `fcmToken`을 읽고 data message를 전송하는 공통 함수다. `title`, `body`, `type`, `reservationId`가 Android 앱에 전달된다. 전송 중 토큰이 만료됐다는 오류가 발생하면 `FieldValue.delete()`로 토큰을 제거한다.

### 3) 앱의 토큰 저장 생명주기

파일: [`FirebaseNotificationRepository.kt`](../app/src/main/java/com/kkm/timelink/data/messaging/FirebaseNotificationRepository.kt)

`syncToken()`은 `FirebaseMessaging.token.await()`로 현재 토큰을 가져와 `saveToken()`에 전달한다. `saveToken()`은 `SetOptions.merge()`를 사용하므로 `user_private` 문서의 다른 필드를 덮어쓰지 않는다. `clearToken()`도 문서 전체를 삭제하지 않고 `fcmToken` 필드만 제거한다.

### 4) 로그인과 로그아웃 시점의 토큰 연결

파일: [`AuthViewModel.kt`](../app/src/main/java/com/kkm/timelink/ui/auth/AuthViewModel.kt)

ViewModel 초기화 시 이미 로그인되어 있으면 `syncNotificationToken()`을 실행하고, Google 로그인 성공 후에도 다시 동기화한다. 로그아웃 시에는 Firebase Auth 세션을 종료하기 전에 현재 UID의 토큰을 제거한다. UID를 잃기 전에 토큰을 지워야 정확한 `user_private/{uid}` 문서를 수정할 수 있다.

### 5) Android 메시지 수신과 시스템 알림 생성

파일: [`TimeLinkMessagingService.kt`](../app/src/main/java/com/kkm/timelink/data/messaging/TimeLinkMessagingService.kt)

`onNewToken()`은 로그인 사용자가 있을 때 새 토큰을 Repository에 저장한다. `onMessageReceived()`는 data message의 제목, 본문, 예약 ID를 읽고 `NotificationCompat.Builder`로 알림을 만든다. Android 13 이상에서는 알림 권한이 있는지 확인하며, `PendingIntent`에 `reservationId`를 넣어 알림 클릭 후 예약 상세 화면으로 연결한다.
