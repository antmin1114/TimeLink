## 1. 상태 끌어올리기와 Stateless Composable

- 사용 위치: [TimeSlotManagementScreen.kt](C:/Users/antmi/AndroidStudioProjects/TimeLink/app/src/main/java/com/kkm/timelink/ui/timeslot/TimeSlotManagementScreen.kt:48) / `TimeSlotManagementScreen`
- 실제 코드 일부:

```kotlin
fun TimeSlotManagementScreen(
    uiState: TimeSlotUiState,
    onDateSelected: (LocalDate) -> Unit,
    onStartTimeSelected: (Int, Int) -> Unit,
    onCreateClick: () -> Unit,
    onDisableClick: (String) -> Unit,
    onEnableClick: (String) -> Unit

```

- 코드가 하는 역할: 화면은 `uiState`를 받아서 표시하고, 사용자 행동은 콜백으로 외부에 전달합니다. 화면이 ViewModel이나 Repository를 직접 알지 않습니다.
- 왜 중요한지: UI와 비즈니스 로직이 분리되어 테스트와 Preview가 쉬워지고, 동일한 Composable을 다른 상태와 이벤트 처리 방식으로 재사용할 수 있습니다.
- 실무에서 언제 사용하는지: MVVM 화면, 폼 입력, 목록 화면, 상세 화면처럼 상태와 이벤트가 많은 거의 모든 화면에서 사용합니다.
- 비슷한 화면에서도 재사용할 수 있는 예시:

```kotlin
@Composable
fun ProfileScreen(
    uiState: ProfileUiState,
    onNicknameChange: (String) -> Unit,
    onSaveClick: () -> Unit
)
```

## 2. 단일 UiState에 따른 선언적 화면 분기

- 사용 위치: [ReservationListScreen.kt](C:/Users/antmi/AndroidStudioProjects/TimeLink/app/src/main/java/com/kkm/timelink/ui/reservation/ReservationListScreen.kt:74) / `ReservationListScreen`

```kotlin
when {
    uiState.isLoading -> item { ReservationLoadingCard() }
    uiState.reservations.isEmpty() -> {
```

- 왜 중요한지: Compose에서는 화면을 직접 변경하는 대신 “현재 상태라면 어떤 UI여야 하는가”를 선언해야 합니다. 이 방식이 선언형 UI의 핵심입니다.

- 비슷한 화면에서도 재사용할 수 있는 예시:

```kotlin
when {
    state.isLoading -> LoadingContent()
    state.error != null -> ErrorContent(state.error)
    state.items.isEmpty() -> EmptyContent()
    else -> ItemList(state.items)
}
```

## 3. LazyColumn의 안정적인 key와 스크롤 위치 유지

- 사용 위치: [TimeSlotManagementScreen.kt](C:/Users/antmi/AndroidStudioProjects/TimeLink/app/src/main/java/com/kkm/timelink/ui/timeslot/TimeSlotManagementScreen.kt:90) / `TimeSlotManagementScreen`
- 실제 코드 일부:

```kotlin
when {
    uiState.isLoading && uiState.timeSlots.isEmpty() -> {
        item { LoadingCard() }
    }

    uiState.timeSlots.isEmpty() -> {
        item { EmptySlotCard() }
    }

    else -> items(
        uiState.timeSlots,
        key = { it.id }
    ) { slot ->
        TimeSlotItem(...)
    }
}
```

- 코드가 하는 역할: 최초 로딩에서만 목록을 로딩 카드로 교체하고, 토글 후 재조회 중에는 기존 항목을 유지합니다. 각 슬롯에는 고유 ID를 key로 제공합니다.
- 왜 중요한지: 목록 전체가 로딩 UI로 교체되면 현재 보이던 항목이 Composition에서 사라져 스크롤이 초기화될 수 있습니다. 안정적인 key는 데이터 갱신 시 Compose가 같은 항목을 식별하도록 돕습니다.
- 실무에서 언제 사용하는지: 좋아요, 즐겨찾기, 활성화 토글, 페이지 갱신처럼 현재 목록을 유지한 채 일부 데이터가 변경될 때 필수적입니다.
- 비슷한 화면에서도 재사용할 수 있는 예시:

```kotlin
LazyColumn {
    items(users, key = User::id) { user ->
        UserItem(
            user = user,
            isUpdating = updatingUserId == user.id
        )
    }
}
```

## 4. `remember`를 이용한 Composable 로컬 상태 관리

- 사용 위치: [TimeSlotManagementScreen.kt](C:/Users/antmi/AndroidStudioProjects/TimeLink/app/src/main/java/com/kkm/timelink/ui/timeslot/TimeSlotManagementScreen.kt:196) / `TimeSelectBox`
- 실제 코드 일부:

```kotlin
var expanded by remember {
    mutableStateOf(false)
}

Surface(
    modifier = Modifier.clickable {
        expanded = true
    }
)

DropdownMenu(
    expanded = expanded,
    onDismissRequest = { expanded = false }
)
```

- 코드가 하는 역할: 드롭다운이 열려 있는지 여부를 Composable 내부 상태로 관리합니다. 상태가 바뀌면 관련 UI가 자동으로 재구성됩니다.
- 왜 중요한지: 모든 상태를 ViewModel로 올릴 필요는 없습니다. 드롭다운, 다이얼로그, 툴팁처럼 일시적인 UI 상태는 해당 Composable 내부에 두는 것이 자연스럽습니다.
- 실무에서 언제 사용하는지: 메뉴 펼침, 비밀번호 표시 여부, 탭 애니메이션, 도움말 팝업 등 서버나 비즈니스 상태와 무관한 UI 상태에 사용합니다.
- 비슷한 화면에서도 재사용할 수 있는 예시:

```kotlin
var showDeleteDialog by remember { mutableStateOf(false) }

if (showDeleteDialog) {
    AlertDialog(
        onDismissRequest = { showDeleteDialog = false },
        confirmButton = { /* ... */ }
    )
}
```

화면 회전이나 프로세스 재생성 후에도 상태를 복원해야 한다면 `rememberSaveable`을 사용해야 합니다.

## 5. 데이터 기반 Select Box 구성

- 사용 위치: [TimeSlotManagementScreen.kt](C:/Users/antmi/AndroidStudioProjects/TimeLink/app/src/main/java/com/kkm/timelink/ui/timeslot/TimeSlotManagementScreen.kt:203) / `TimeSelectBox`
- 실제 코드 일부:

```kotlin
val options = remember(includeEndOfDay) {
    buildList {
        for (hour in 0..23) {
            add(hour to 0)
            add(hour to 30)
        }
        if (includeEndOfDay) add(24 to 0)
    }
}

options.forEach { (hour, minute) ->
    DropdownMenuItem(
        text = { Text(formatTime(hour, minute)) },
        onClick = {
            expanded = false
            onTimeSelected(hour, minute)
        }
    )
}
```

- 코드가 하는 역할: 30분 간격 시간 데이터를 생성하고, 같은 데이터로 드롭다운 항목을 반복 렌더링합니다. 종료 시간만 `24:00`을 포함합니다.
- 왜 중요한지: 옵션을 직접 여러 줄 작성하지 않고 규칙으로 생성하면 중복이 줄고 변경이 쉬워집니다. UI가 데이터에서 파생되는 Compose의 장점을 잘 활용한 구조입니다.
- 실무에서 언제 사용하는지: 시간, 국가, 카테고리, 정렬 방식, 수량처럼 정해진 선택지를 표시할 때 사용합니다.
- 비슷한 화면에서도 재사용할 수 있는 예시:

```kotlin
val durations = listOf(30, 60, 90)

durations.forEach { duration ->
    DropdownMenuItem(
        text = { Text("${duration}분") },
        onClick = { onDurationSelected(duration) }
    )
}
```

```kotlin
    icon: ImageVector,
    label: String,
    value: String
```

## 9. Modifier 순서와 클릭 가능 영역 설계

- 사용 위치: [HomeScreen.kt](C:/Users/antmi/AndroidStudioProjects/TimeLink/app/src/main/java/com/kkm/timelink/ui/home/HomeScreen.kt:208) / `MenuCard`
- 실제 코드 일부:

```kotlin
Surface(
    modifier = modifier
        .fillMaxWidth()
        .clickable(
            enabled = enabled,
            onClick = onClick
        ),
    shape = RoundedCornerShape(18.dp)
)
```

시간 선택 필드에서는:

```kotlin
Surface(
    modifier = Modifier
        .fillMaxWidth()
        .height(48.dp)
        .clickable { expanded = true }
)
```

- 코드가 하는 역할: 화면에 보이는 카드나 필드 전체를 클릭 대상으로 만들고, 처리 상태에 따라 클릭을 차단합니다.
- 왜 중요한지: Compose의 Modifier는 선언 순서에 따라 측정, 배치, 그리기, 입력 처리 결과가 달라질 수 있습니다. 클릭 가능한 영역을 텍스트에만 붙일지 카드 전체에 붙일지도 UX에 큰 영향을 줍니다.
- 실무에서 언제 사용하는지: 카드형 메뉴, 목록 항목, 선택 필드, 로딩 중 버튼 비활성화 등에 사용합니다.
- 비슷한 화면에서도 재사용할 수 있는 예시:

```kotlin
Row(
    modifier = Modifier
        .fillMaxWidth()
        .clickable(enabled = user.isActive) {
            onUserClick(user.id)
        }
        .padding(16.dp)
)
```

`clickable`과 `padding` 순서를 바꾸면 클릭 영역이 달라질 수 있으므로 의도적으로 배치해야 합니다.

## 10. Canvas를 이용한 가벼운 커스텀 그래픽

- 사용 위치: [ReservationListScreen.kt](C:/Users/antmi/AndroidStudioProjects/TimeLink/app/src/main/java/com/kkm/timelink/ui/reservation/ReservationListScreen.kt:273) / `ReservationArtwork`
- 실제 코드 일부:

```kotlin
Canvas(modifier) {
    val purple = Color(0xFF7772F8)

    drawRoundRect(
        color = purple.copy(alpha = .18f),
        topLeft = Offset(size.width * .13f, size.height * .23f),
        size = Size(size.width * .62f, size.height * .5f),
        cornerRadius = CornerRadius(12f)
    )

    drawCircle(
        color = purple.copy(alpha = .45f),
        radius = size.width * .24f,
        center = Offset(size.width * .76f, size.height * .7f),
        style = Stroke(3.dp.toPx())
    )
}
```

- 코드가 하는 역할: 현재 Canvas 크기를 기준으로 도형을 그려 캘린더와 시계 형태의 장식 이미지를 만듭니다.
- 왜 중요한지: 단순한 아이콘이나 장식은 이미지 리소스를 추가하지 않고도 해상도 독립적으로 표현할 수 있습니다. 색상이나 크기도 런타임에 쉽게 변경할 수 있습니다.
- 실무에서 언제 사용하는지: 진행률 표시, 차트, 배지, 파형, 간단한 일러스트, 디자인 시스템 전용 아이콘을 만들 때 사용합니다.
- 비슷한 화면에서도 재사용할 수 있는 예시:

```kotlin
@Composable
fun ProgressRing(progress: Float) {
    Canvas(Modifier.size(48.dp)) {
        drawArc(
            color = Color.Blue,
            startAngle = -90f,
            sweepAngle = progress * 360f,
            useCenter = false,
            style = Stroke(4.dp.toPx())
        )
    }
}
```

복잡한 일러스트나 접근성이 중요한 아이콘은 Canvas보다 벡터 리소스나 Material Icon을 사용하는 편이 관리하기 좋습니다.
